📋 Engagement brief — HexaFit Inc

Client: HexaFit Inc, a (fictional) fitness-tracking startup. Their mobile apps talk to this Flask REST API: members register, log workouts, collect points and redeem them for physical rewards. Points are worth money, premium status is worth money, and the API has never been tested by anyone who didn't write it. A retail partner wants a security assessment before integrating the rewards programme. You are the assessor.

Scope: this API and its companion web profile page — every route on this host and port. The seeded accounts and your own registered account are in scope. Other ports and other labs are out of scope, exactly as on a real engagement.

Working method: this is an API engagement. There is almost no UI to click — drive the API with Burp Repeater or curl, capture a real login token, decode it, and build from there. The companion profile page at /profile/<id> is part of the product and in scope.

Rules of engagement: no denial of service, no deleting other members' data beyond what a test needs to prove, and everything you do is logged (see the Logs page — API calls included).

How scoring works: twelve tests are scored server-side the moment your action is detected — for example, the server notices when a token it never issued actually authenticates as admin, or when a redemption credits points the balance could not cover. Work black-box first; open the Code Review only for your second pass.

Deliverable: at 100% you will write one mini finding in professional format on the Complete page.

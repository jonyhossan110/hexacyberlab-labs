# HexaAPI — Vulnerabilities Map (LAB 21)

LAB 21 wraps the original HexaAPI platform (18 flaw groups, OWASP API Security Top 10 2023) in the HexaCyberLab lab system: an entry-key gate (Lab 20's completion key), a scored TESTS registry of **25 tests across 8 features**, server-side detection of each exploit's real effect, per-feature attempt counting, the Lab Coach chatbot (help unlocks after 3 attempts on a feature), persistent progress (progress.json), a completion debrief at /complete and a certificate at /certificate.

## Scored test registry — grouped by feature

### Authentication & Tokens (4)

- **Brute Force — No Rate Limit on API Login** — API2 Broken Authentication · Beginner. An unthrottled login endpoint makes online password guessing free and quiet; weak passwords fall in minutes.
- **JWT Forgery — alg=none & Weak Leaked Secret** — API2 Broken Authentication · Intermediate. Token verification must pin the algorithm, reject unsigned tokens outright, and protect a strong random secret — a hand-rolled verifier gets all three wrong.
- **Token Lifecycle — Logout & Password Change Revoke Nothing** — API2 Broken Authentication · Beginner. Stateless tokens without a revocation story cannot be killed: logout and password changes must invalidate outstanding tokens (denylist or token versioning), and lifetimes must be short.
- **OTP Brute Force — 4-Digit Code, Unlimited Attempts** — API6 Unrestricted Access to Sensitive Business Flows · Beginner. Short codes plus unlimited verification attempts equal no second factor at all; attempt counters and expiry are part of the control, not extras.

### Registration & Accounts (4)

- **Account Enumeration — Register & Login Oracles** — API2 Broken Authentication · Beginner. Auth-adjacent endpoints must answer uniformly; a differing response turns registration and login forms into a user-directory lookup.
- **Mass Assignment — Privilege Fields in Register & PATCH** — API3 Broken Object Property Level Authorization · Beginner. Bind only allowlisted fields per endpoint; role, tenant and admin flags must never arrive from the client.
- **Weak Password Policy — 1-Character Passwords Accepted** — API2 Broken Authentication · Beginner. A password policy is cheap defence-in-depth: minimum length and breached-password checks remove the weakest tier of accounts.
- **Stored XSS — Script Payload in a User Name Reaches the Admin Console** — A03 Injection (XSS) · Intermediate. Output encoding must be contextual and universal — one unescaped render point poisons every viewer, including staff.

### Object Access (BOLA) (3)

- **BOLA — Cross-Company Orders, Users & Invoices by ID** — API1 Broken Object Level Authorization · Beginner. Every object fetch must verify the object belongs to the caller’s tenant — the ID in the URL is not an authorisation check.
- **Parameter Pollution — ?company_id= Overrides Your Tenant** — API1 Broken Object Level Authorization · Beginner. Tenant scope is a server-side fact derived from the authenticated identity; client parameters may filter within that scope, never widen it.
- **GraphQL BOLA — Cross-Company User Resolution** — API1 Broken Object Level Authorization · Intermediate. GraphQL resolvers need the same per-object authorisation as REST handlers; a new protocol surface does not inherit the old checks automatically.

### Admin & Function Access (2)

- **BFLA — Admin Functions Without an Admin Check (+ X-Admin Header Trust)** — API5 Broken Function Level Authorization · Beginner. Function-level authorisation must be enforced server-side on every route, and roles must come from the authenticated session — never from client-supplied headers.
- **GraphQL BFLA — Role Mutation for Any Caller** — API5 Broken Function Level Authorization · Intermediate. Every mutation is a privileged function: apply the same role and tenant checks as the equivalent REST endpoint.

### API Keys (3)

- **API Key Scope Never Enforced — Read-Only Key Deletes Users** — API2 Broken Authentication · Beginner. Scopes are authorisation decisions: enforce them on every route, or do not pretend they exist.
- **Predictable API Keys — Pattern Gives Away Every Company’s Keys** — API2 Broken Authentication · Beginner. API keys are credentials: they need unguessable random material, not a company name and a counter.
- **API Keys Accepted in the URL Query String** — API2 Broken Authentication · Beginner. Credentials belong in headers, never URLs; servers must reject query-string keys so they cannot leak through logs and history.

### Data Exposure & Exports (3)

- **Excessive Data Exposure — Full User Records incl. Password Hashes** — API3 Broken Object Property Level Authorization · Beginner. Serializers must be per-endpoint allowlists; returning the database row ‘because it is convenient’ leaks credentials and PII by default.
- **Export Leak — Users CSV Contains Every Company** — API3 Broken Object Property Level Authorization · Beginner. Exports must be scoped to the caller’s tenant and minimised to business-necessary fields; treat bulk export as a privileged, logged function.
- **Debug Config — JWT Secret & Internals, No Auth** — API8 Security Misconfiguration · Beginner. Debug and diagnostics endpoints must never ship reachable in production; if retained, they need hard authentication and network restrictions.

### Integrations & Webhooks (3)

- **SSRF — URL Fetcher & Webhook Tester Reach Internal Endpoints** — API7 Server Side Request Forgery · Intermediate. Any server-side URL fetch needs scheme/host allowlisting and private-range blocking after DNS resolution — otherwise it is an internal-network proxy.
- **Unsafe Consumption — Import Feed Creates Privileged Accounts** — API10 Unsafe Consumption of APIs · Intermediate. Third-party data is untrusted input: validate against a strict schema and never import privilege fields — assign least-privilege defaults instead.
- **Forged Webhooks — Payment Events Accepted Without a Signature** — API8 Security Misconfiguration · Beginner. Webhook receivers must verify an HMAC signature and a replay window per endpoint secret; webhook-driven state changes are financial transactions.

### Platform & Inventory (3)

- **Improper Inventory — Legacy v1 Live Without Auth + Undocumented /internal/*** — API9 Improper Inventory Management · Beginner. Maintain a full API inventory: retire or fully secure old versions, and keep internal endpoints on a separate, access-controlled interface.
- **Unrestricted Resource Consumption — Uncapped Limits & Expensive Reports** — API4 Unrestricted Resource Consumption · Beginner. Every list needs a server-side page cap and every expensive operation a cost budget; unbounded client-chosen work is a denial-of-service feature.
- **GraphQL Introspection — Full Schema Disclosed to Any Caller** — API8 Security Misconfiguration · Beginner. Introspection belongs in development; production GraphQL needs it disabled, plus depth/cost limits and per-field authorisation.

## The 18 flaw groups — deep map

Every flaw is marked in `server.js` with a `// VULN(<n>):` comment. Group numbers are canonical across this file, `DESIGN.md`, the in-app `/lab-guide` and the code markers. Hints only — prove each one yourself, then read the Fix. All 18 groups were verified end-to-end by the scripted run recorded in `BUILD-TESTS.md`.

**★ Capstone chain (group it yourself):** the groups combine into a full platform takeover — debug config leaks the secret (9) → forge an operator token or send alg=none (2) → internal export dumps every user with hashes (10 + 16). The scripted proof of exactly this chain is the last check in `BUILD-TESTS.md`.

**Standing note:** the seeded accounts and keys are *documented in the README and on the login page* — in a real report, "default/documented credentials" is itself a critical finding. That is deliberate here: this is a lab, and the printed passwords are how you get in.
